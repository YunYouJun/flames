# 全异火还原基础约定

这份约定锁定完整异火榜的身份、路由、视觉家族与验收边界。九个家族、23 席均完成实时实现；本次按用户“完善所有异火并提交推送”的授权收尾并统一开放，不再要求逐席手动确认。

## 席位与来源

- 榜单保留 23 个稳定路由；第 2–23 位是基础还原范围，第 1 位帝炎是全部基础异火完成后的终局项目。
- 视觉状态分为 `reserved`、`assigned`、`prototype`、`approved`。生产环境只有 `approved` 加载实时引擎；其余状态显示 SSR/CSS 封印态并设置 `noindex`。
- 原著明确、授权扩展、项目演绎分别标注。第 18、20、21 位采用风怒龙炎、幽冥毒火、阴阳双炎作为扩展身份；风雷怒焱、龙凤焱、六道轮回炎只作为其他衍生版本展示。
- `apps/web/app/data/flames.ts` 是名称、名次、slug、来源、状态和视觉 brief 的唯一元数据来源。Markdown 仅可按 `flameId` 补充长文。

## 性能门槛

- resident programs `≤ 17`；单席 active programs `≤ 6`（含承台、体积与合成）。
- draw calls：High `≤ 32`、Balanced `≤ 25`、Lite `≤ 8`；体积合成比平面路径多一次绘制。
- 单详情页初始 JavaScript 目标 gzip `≤ 250 KiB`，硬上限 `≤ 300 KiB`。
- 单个客户端 chunk 原始体积在 `> 600 KiB` 时预警，硬上限 `≤ 800 KiB`；后续按 kernel 拆分加载后再重新收紧。
- CSS gzip `≤ 15 KiB`，完整静态产物 `≤ 3 MiB`。
- 每个家族代表作必须没有 shader compile error、page error 或 console error。
- 体积采样目标像素限制为 Balanced `≤ 300,000`、High `≤ 600,000`，任一轴不超过 4096；龙形、叶焰等细轮廓使用较高采样比例，切换画质或席位时重新计算。此上限不代表真实设备帧率保证。

在已批准路由后附加 `?benchmark=1&quality=balanced` 可固定动画时间与初始画质。固定画面按需重绘，旋转、点按、长按、尺寸或画质改变仍会刷新；交互衰减完成后停止重复 GPU 绘制，普通播放不受影响。Canvas 会通过只读 `data-*` 暴露 renderer diagnostics，供 E2E 对 resident program 与 draw call 预算做机械验证。此模式不用于 FPS 测量，也不作为真实设备性能结论。

## 3D 评审路径

### 分批精修进度

以下为历史批次记录，其中“待评审”描述各批结束时的状态；当前发布状态以上表和下方收尾记录为准。

- A 批三莲：已拆分体积轮廓（青莲低展、净莲托焰、红莲闭卷），莲瓣根部按承台火源定位，长按直接改变莲瓣展开比例。当前待视觉评审，不视为最终定稿。
- 红莲外围焰丝借鉴石蒜反卷、放射的形态，属于项目演绎；红莲与彼岸花不等同，不改变莲形主体或新增能力设定。
- B 批首轮：虚无外焰加入内收的断续螺旋，金帝加入错相局部涡流，骨灵加入随长按扩张的冷焰环；仍待动态视觉评审。
- C 批首轮：生灵叶焰错峰生长，海心浪尖内卷，云水双层焰幕与下行焰丝，毒池鼓泡与双侧探焰。控火偏转覆盖家族体积轮廓；仍待视觉评审。
- C 批细化：生灵从椭球改为连茎尖叶与高亮中脉，限制局部扰动防止叶尖翻折；云水从圆环改为双层起伏薄面，加入破边和冷热配色，独立调整薄层消光以改善辨识度。
- D 批首轮：九幽横向七层风带与空眼、风怒双股旋焰与鬃焰、三千纵向星弧龙身、九龙三层各三处雷焰源及断续弧尾。仍属项目演绎，未改变公开状态。
- D 批细化：风龙、星龙与九龙复用带长吻、口缝、眼窝及后掠角的密度轮廓，压低风龙和星龙的纯白核心比例；仍需动态辨识度评审。
- 龙首二次精修：分离上下颌与颈部，补鼻孔、压眉、分叉角和摆动龙须；头部保留控火偏转但不使用躯干的大幅随机扭曲。逐采样点分离面部密度、遮罩与眼线发光，避免躯干填亮口缝；长按可张颌、亮眼，风龙与星龙同时抬首。九龙头部略放大，仍保留三层九首；以上均为视觉演绎，不新增原著能力设定。
- E 批首轮：龟灵改为分片薄甲与尾焰，万兽外围错峰浮现七处小兽影，陨落心炎增加绕心细蟒和衰减脉冲环，阴阳双流补充底部火印；均为项目演绎，仍待视觉评审。
- F 批细化：八荒改为左右后掠火翼和错相翼脊，金祖加入断纹与分段约束环，火山石焰增加共享石材的七块合并岩体。玄黄保留低矮火种，不扩大为山岳形态。
- 全席补全：万兽取消固定单一巨兽首，红色主焰外错层交替浮现尖耳、圆耳短吻与角形兽面；长按使七处兽影共同显形，可先旋转再长按查看背侧。数量和兽面类别是项目演绎，不新增召唤或统御能力。
- 龟灵补充背刺、獠牙和粗尾；陨落心炎去除实心双叶核，改为低密度蟒焰与双段心火热环。虚无按压使外焰内收、九幽风炎按压增强横风卷幅。
- G 帝炎已补齐四层错相冠环、十一道内收辐线与近无色焰核，纳入全席工程检查；终局发布仍后置，不因实装完成改变公开状态。

### 全席发布收尾

- 帝炎以更高的主焰、三股向心焰幕连接四层冠环，减轻散落光圈感；八荒补强翼间轴向火体和灰白热边，确保 90° 侧视仍能读出火焰。
- 龙首上下颌、万兽颊吻和龟灵头足采用带转折的截面；流动火纹保留明暗断裂，减少圆球堆叠感。九龙增加层间距与轨道半径，保留九处龙首。
- 九幽横风错相漂移并改变展幅，云水加厚连接焰丝，毒池加入不规则薄面和空心泡；陨落心炎增加细蟒可见度但不恢复实心心脏，阴阳黑焰保留暗芯并补克制的灰紫边缘。
- 本次开放剩余 17 席并同步九家族状态，开发和生产均使用同一套批准名单。原著、扩展与项目演绎的来源标记保持不变；开放不等于官方资产、逐章原文考据或影视级保真。

### 技术与验收约束

- 所有家族的精细、均衡档使用对象空间体积采样；轻量档保留原平面 shader。此升级不自动改变席位的公开审核状态。
- `volume-fields.ts` 按家族和变体定义三维密度：空心吞噬壳、莲心、冷焰棱脊、潮汐／叶片／云层／毒池、风涡／龙形、雷轨／星火／龟壳／兽首、心焰／阴阳双流、火冠／翼焰／祖碑、岩火／火种。
- `VolumeFlame` 管理噪声纹理、独立低分辨率采样和透明合成；已有莲瓣、吞噬核心、潮汐环进入同一体积场景。承台保持全分辨率。
- 3D 档支持水平整圈拖拽和自动环绕（30 秒一圈，默认关闭）；手动调角、复位、暂停或切换席位会停止自动环绕。按下先进入待判定，停留 250 ms 才蓄焰；移动达到 8 CSS px 后交给拖动，且来回拖动不再被误判为点击。开启旋转时直接拖动不触发蓄焰，关闭后拖动拨焰。状态面板区分按住待判定、蓄焰中、环视中和拨焰中。
- 蓄焰转为旋转或正常松手时，焰压按 600 ms 平滑曲线回落；连续拖动不重置淡出计时。点按和淡出均独立于场景动画时钟，暂停／减少动态效果下仍保留主动操作反馈；软件 WebGL 卡顿时限制单帧交互步长，实际回落时间可能延长。
- 短点击的独立焰压包络约 1.1 秒，不依赖场景动画时钟。低帧率时限制单次消耗的交互时间，使一次卡顿不会吃掉整个脉冲；此时实际持续时间会延长。暂停、减少动态效果下仍支持主动点按与 Enter / Space 唤焰，不恢复背景动画。
- 指针取消、捕获丢失、窗口失焦、切换席位或画质都会清理控火状态，避免残留蓄焰。手机保留画质选择入口，普通页面的 `?quality=high|balanced|lite` 同样生效。
- 分数像素比下先统一主画布与体积合成返回时的视口取整；避免 DPR 1.5 时静止首帧与首次交互后的承台出现一个物理像素的偏移。手机火山石焰的点按衰减检查覆盖此回归。
- 环绕面板在桌面侧置；窄屏为其保留独立顶部空间，避免遮住龙首与焰尖。
- 每席至少对照正面与 90° 侧面，并检查移动端、轻量降级、控制台和绘制预算。体积造型仍属于项目视觉演绎，不等同于官方模型或物理流体模拟。
- `tests/e2e/acceptance.spec.ts` 从唯一席位元数据生成 23 席 × 桌面/手机的验收用例：静止基线、点按差分和衰减、长按、侧视、真实画质控件切换、三档绘制预算、控制台与无横向溢出。快速脉冲用 Chromium 合成帧截图检查，避免软件 WebGL 的普通截图准备过程错过短暂反馈；这不是 GPU 帧率测试。
- `tests/e2e/gesture.spec.ts` 单独覆盖桌面鼠标和模拟触控的长按→旋转淡出、直接拖动不闪蓄焰、松手不误点、取消待判定与拨焰模式。淡出分段像素比较使用浏览器受控时钟，避免截图延迟吞掉短动画；手势与包络边界另由纯逻辑单测验证。
- 工程验收、项目视觉演绎检查、用户视觉批准、真机性能属于独立结论；测试通过不自动修改 `approved` 状态，也不代表逐章原文考据或影视级资产保真。
- 全席浏览器用例还校验 `approved`、可索引、22 席基础进度、帝炎开放及无原型标签；单元测试覆盖禁止提前开放帝炎的回退边界。家族回归按单席拆分，每席 90 秒；全套三档画质与交互检查每席 180 秒。合成帧读取独立允许 30 秒，保留原像素阈值，长按测试确认手势开始后才推进受控时钟。以上是软件 WebGL 的功能检查等待，不是帧率门槛。
- CI 桌面与手机各分四组、每组单 worker；全席三档画面与其余交互分别分片，避免重绘用例集中在首组。两套测试分别保留追踪目录，并在任务期限前结束以留出上传时间。`tests/e2e/rendering.spec.ts` 实际计数 GPU 绘制提交，验证固定画面闲置、旋转／点按重绘及衰减后再次闲置。
- 发布必须重新通过 `build`、`generate`、类型与规范检查，并检查静态产物中的 23 席均可加载实时画布且可索引。600 KiB 单 chunk 预警及 250 KiB gzip 目标仍保留，不因开放所有席位抬高硬门槛。
